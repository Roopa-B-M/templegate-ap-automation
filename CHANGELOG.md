# Changelog

## v1.1 — Scope-closure release

Backward compatible: existing URLs, roles, demo accounts, seed data and
migrations keep working (new migrations only; none of the existing ones were
edited).

### Added
- **Accounting / ERP integration** (new `accounting` Django app):
  - `ERPConnector` interface (same pattern as the payments `BankGateway`) with
    `TallyXMLConnector` (Tally-compatible XML purchase voucher export) and
    `SimulatedERPConnector` (posts a voucher locally and returns an ERP
    reference); generic CSV and JSON export helpers.
  - Models `GLAccountMapping` (default + per-vendor ledger mapping) and
    `ERPSyncLog` (one row per posting attempt, status NOT_SYNCED/SYNCED/FAILED).
  - `erp_status` / `erp_reference` columns on Invoice (migration `invoices.0002`).
  - Endpoints under `/api/accounting/`: sync-log list, `post-invoice/{id}/`,
    `bulk-export/` (date range + format), `retry/{id}/`, mappings CRUD,
    connector status. Finance/Admin only; only APPROVED/PAID invoices postable.
  - New "Accounting / ERP" page (role-gated menu item) with bulk export,
    sync-log table, retry and mapping settings; "Post to ERP" panel on the
    invoice detail page.
- **Banking integration**:
  - Settings-driven gateway selection `BANK_GATEWAY=simulated|file`.
  - `FileBankGateway`: bulk NEFT/RTGS payment-instruction CSV for selected
    scheduled payments (Payments page → "Bank file").
  - Bank statement reconciliation: upload a CSV (UTR, amount, date) to mark
    matching payments PROCESSED + reconciled (`is_reconciled`, `reconciled_at`
    columns, migration `payments.0002`); unmatched rows are reported.
  - Simulated mode clearly labelled in the Payments page.
- **Extraction**:
  - Optional AI assist (`AI_EXTRACTION_PROVIDER=llm`, off by default, no hard
    dependency, graceful fallback) used only when rule-engine confidence is
    below `AI_ASSIST_CONFIDENCE_THRESHOLD` or mandatory fields are missing;
    results merged field-by-field with the supplying engine recorded.
  - Multi-frame TIFF OCR: frame-by-frame via PIL `ImageSequence`, merged text
    and correct `page_count`.
  - Engine + per-field confidence shown on the invoice review screen.
  - Wording corrected everywhere to "rule-based extraction with optional AI assist".
- **Background automation**:
  - Guarded in-process scheduler (`core/scheduler.py`, APScheduler) started
    from `CoreConfig.ready()`/`wsgi.py`: never starts under migrate/test/shell,
    single start under the autoreloader. Jobs: workflow escalation+reminders,
    pending OCR catch-up, IMAP inbox polling (only if configured).
  - Email notifications for approval requests, reminders and escalations via
    the Django email backend (console backend by default).
- **Email ingestion demo**: `manage.py ingest_folder <path>` command; the
  upload page "Simulate email" dialog documents the folder shortcut.
- **Sample data**: top-level `sample_invoices/` (valid invoices for 3 vendors,
  duplicate, wrong-GSTIN, PO amount mismatch, multi-page PDF, scanned PNG,
  multi-page TIFF) generated by `manage.py generate_sample_invoices`;
  `scripts/make_test_invoice.py` CLI (vendor/PAN/state/PO/line-items options,
  prints the valid mod-36 GSTIN).
- **Tests**: proper Django test package `backend/tests` (79 tests) covering
  validators, the validation engine, 2-way/3-way matching, the approval
  workflow (parallel + escalation), the payment lifecycle, the new accounting
  exports, multi-page TIFF and the scheduler guard. `tests/api_integration.py`
  remains the standalone end-to-end HTTP script.
- **Mobile / PWA**: mobile-first Approvals page (card layout, large
  approve/reject buttons, responsive comment dialog); installable PWA
  (manifest, icons, service worker that never caches API/media calls);
  notification menu and layout checked at 360/768/1280 px.
- **Ops**: optional `docker-compose.yml` + Dockerfiles (postgres/backend/
  frontend); `scripts/setup_mac_linux.sh`, `start_mac_linux.sh`,
  `setup_windows.bat`, `start_windows.bat`; `backend/schema.sql` regenerated
  from the final migrations.
- **Docs**: `docs/SCOPE_COVERAGE.md` traceability matrix (every scope bullet →
  implementing files/endpoints/pages with honest status), updated
  `docs/DATABASE_SCHEMA.md`, `CHANGELOG.md`, rewritten `README.md`, every new
  env variable documented in `.env.example`.

### Changed
- Demo company GSTIN default corrected to a checksum-valid value
  (`27AABCT1234A1Z0`) so generated documents validate.
- `payments/services.py` uses `get_bank_gateway()` (setting-driven) while
  keeping module-level `GATEWAY` for backward compatibility.
- `core/apps.py` registers the new accounting models with the audit tracking.
- `frontend/.env` removed from the package (`.env.example` is the template).

### Fixed
- `FileBankGateway.generate_bulk_file` referenced `self` inside a static
  method (found by the new test suite).
- Bank statement reconciliation was missing the `Invoice` import.
- Payments table "Requested By" column read a non-existent serializer field.
- Multi-page TIFF was always OCR'd as a single frame.
